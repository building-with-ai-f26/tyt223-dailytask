# AGENTS.md — Coding Agent Operating Manual

> Give this file to your coding agent and check that it is using these instructions. Keep the stack, commands, and ground rules current.

## 1. Project Overview
- **What this repo builds:** DailyQuest, a gamified task planner for busy MBA students. Users type tasks in plain English, see only today's quests, and earn XP, levels, streaks and real-life rewards for finishing them.
- **Primary user & core workflow:** First-year NYU Stern MBA students checking in on their phones. Full PRD in `docs/index.html`; durable product facts in `PRODUCT.md`.
- **Tech stack:** One static HTML file with plain CSS and JavaScript (no framework, no build step, no packages). Data in the browser's `localStorage`, plus optional accounts (Supabase Auth: email + password) that sync each user's save to a Supabase `saves` table protected by Row Level Security; `supabase-js` loads from jsDelivr (pinned version with an integrity hash) only when accounts are configured. Hosted free on GitHub Pages from the `docs/` folder. External calls from the browser: Nager.Date public holidays API (free, no key), PostHog analytics, Google Fonts. Backend on Supabase's free plan: Auth, Postgres (RLS on every table), four Edge Functions (`fetch-calendar`, `send-reminders`, `suggest`, `ai-tools`) and a `pg_cron` job every 15 minutes. AI typing suggestions on the live site come from the `suggest` function (OpenAI key in Supabase secrets, signed-in users only, 30/hour per user, daily cap); the local `server.js` (Node built-ins, no packages) does the same on the builder's computer. Security audit: `SECURITY.md`.
- **Live URLs:** Product Page https://building-with-ai-f26.github.io/tyt223-dailytask/ · App https://building-with-ai-f26.github.io/tyt223-dailytask/app/
- **Firm constraint:** free hosting ($0); AI stays optional and capped: signed-in users only, per-user and daily limits, an OpenAI monthly budget, and history suggestions when AI is off. See `PRODUCT.md`.

### How the app code is organized (`docs/app/index.html`)
- **Design tokens** (colors, fonts, shadows, corner ornaments) are CSS variables at the top of the `<style>` block; journal themes override `--accent` and the `--leather`/`--sky` colors. The look is an elegant fantasy quest journal (see `PRODUCT.md` → Brand Commitments): paper panels with torn edges come from the `#paper-edge` SVG filter applied to `::before` backgrounds only, so text stays crisp.
- **Game numbers** (`XP_BY_DIFFICULTY`, bonuses, `XP_PER_LEVEL`, `SHIELD_PRICE`, `CHEST_MIN`/`CHEST_MAX`, `ACHIEVEMENT_COINS`) sit at the top of the script; several are placeholders.
- **Pure logic** (`parseEntry`, `parseIcs`, `holidaysToEvents`, `completeQuest`, `checkInGoal`, `claimReward`, `applyEdit` and others) never touches the page, so it can be tested in Node.
- **Page code** starts at `// ---------- Page code ----------`: `render*` functions build each tab, and one `click`, `submit` and `change` listener each route actions by `data-action`.
- **Swipe and stamp:** cards with `data-swipe` (unfinished quests, due routines/goals) respond to touch swipes (`swipeStart/Move/End`): right clicks the card's own complete/check-in button, left reschedules to tomorrow (quests only). `finishQuest` presses the gold `DONE` stamp before the card leaves.
- **Smart compose:** `historySuggestion` (pure) matches what's typed against `suggestionSources` (newest quests and routines, then templates). The page code (`updateSuggestion`, `askAi`, `acceptSuggestion`) asks for an AI ending only when history has no match, after a 350 ms pause: from `server.js` if `detectAi` found it on localhost, otherwise from the `suggest` Edge Function when signed in (`cloudAiReady`, `askCloudAi`; a 429 or 503 switches cloud AI off for the session).
- **Storage key** is `dailyquest.v2`. Changing the saved data shape needs a migration, or users lose their data (in the browser and in Supabase, which stores the same object).
- **Accounts:** `SUPABASE_URL` and `SUPABASE_KEY` (the public publishable key; never the secret/service_role key) sit under `// ---------- Accounts`. Empty means accounts are off. `save()` calls `markChanged()`, which uploads the save about a second later (`pushNow`). Sync bookkeeping lives in a separate key, `dailyquest.sync` (`{ user, syncedAt, pending }`). At login the pure `syncPlan()` picks upload, download, none or ask. Logging out clears the browser copy. While accounts are on and nobody is logged in, the Profile tab shows `sealedProfile()` (wax-sealed card, Get the app panel, blurred preview) instead of avatars, stats, theme and data tools.
- **Connected calendars:** `state.feeds` (`{ id, name, url, lastSync, error }`, optional, defaults to `[]`) lives in the save. `refreshFeed` calls the `fetch-calendar` function, parses with `parseIcs`, and `replaceFeedEvents` swaps that feed's events (`source: "feed:<id>"`). Feeds refresh after login and when the app comes back if older than 1 hour, and every 3 hours while open. The feed URL is a secret link; never send it to PostHog.
- **Calendar → quests:** on each feed refresh (when the feed's **Make quests** switch is on, the default), `syncAutoQuests` turns deadline events (`deadlineName`: "… - Due", "Availability Ends", "End Date"…) into Class quests and coffee chats/interviews (`followUpPerson`) into next-day thank-you quests. Auto-quests carry `autoFrom` (feed id) and `autoKey` (event key); deleted ones go into `state.autoDismissed` and are never re-created; moved deadlines move unless the player moved the quest.
- **Weekly boss:** `BOSSES` (13×13 sprites), `ensureBoss` (new boss each Monday; HP = `BOSS_HP_SHARE` × planned damage, clamped to `BOSS_MIN_HP`/`BOSS_MAX_HP`) and `hitBoss` (called inside `completeQuest`/`checkInGoal`, so Undo also reverts hits and loot). `state.boss`, `state.bossesDefeated`; Week shows `bossCard`, Today shows `bossStrip`.
- **Gear and map:** `GEAR` (pets with 13×13 sprites, portrait frames, titles), `buyGear`/`equipGear` and `state.gear` (`{ owned, pet, frame, title }`); `renderPlayer` draws the pet, frame and title in the HUD. `MAP_LANDMARKS`, `mapProgress(daysCleared)` and `adventureMap()` draw the Profile trail (30 steps per journey) as a hand-drawn SVG storybook map (pen-and-ink scenes, `inkWobble` filter, handwritten margin notes); landmark medallions are HTML buttons (`landmark-info`) that open `openLandmark()` with `LANDMARK_LORE` and the reward. Label offsets live in `LABEL`; check for overlaps after moving anything. Landmarks carry a `reward` (gear or coins; the `dragonslayer` title is journey-only, `price: null`); `claimLandmarks` pays each one once per journey (`state.landmarksClaimed`, owned gear pays `LANDMARK_OWNED_COINS`) right after a day is cleared. Profile has chapter tabs via `profileTabs`/`profileMode`: Journey (map, badges, achievements), Hero (avatar, hero stats, stats), Settings (account, app & reminders, theme, data, demo tools).
- **Friends:** Profile's Friends chapter (`friendsPage`). `social` holds the player's card (`social.me`) and `friend_list()` rows; `loadSocial` runs after login and when the chapter opens, `syncHeroCard` updates the card after each save upload, but only `heroCardStats` (avatar, level, streak, weekly XP, week); never send quest names to `profiles`. Invite links `?friend=CODE` are caught by `captureInvite` (kept in `sessionStorage` until login) and offered by `maybeInvite`. Pure helpers: `newFriendCode`, `cleanHeroName`, `friendCodeFrom`, `xpBetween`, `leaderboard`.
- **AI tools:** the **✦ Paste notes** chip (`openPaste` → `findPastedQuests` → `openPasteReview` → `addPastedQuests`) never adds anything without the player's review. The Week tab's `chroniclePanel` calls `writeChronicle`, which sends `chronicleStats(today)` (counts and a few names only) and stores the result in `state.chronicles[weekMonday]` (optional, synced with the save). Both go through `callAiTools`, which turns 401/429/503 into friendly messages.
- **Reminders:** `PUSH_PUBLIC_KEY` (public half of the VAPID pair) and `reminderControls` (shown inside the app panel once installed), `pushOn`, `pushOff`, `pushTest` sit under `// ---------- Reminders`. Turning on saves the device's push subscription and time zone to `push_subscriptions`; logout calls `pushOff(true)`. `sw.js` shows pushes and opens the app on tap. Newer Supabase projects grant no table access by default, so new tables need explicit grants (see `reminders.sql`).
- **Analytics:** `track(event, props)` sends PostHog events. Never send task or reward names, or emails (account events: `login`, `signup`, `logout`, `sync_choice`; reminders: `reminders_on`, `reminders_off`; AI tools: `paste_quests_found`, `paste_quests_added`, `chronicle_written`, counts only; friends: `hero_card_created`, `friend_search`, `friend_request_sent`, `friend_added`, `invite_shared`, never names or codes). Session replay masks all text in the app.

## 2. Commands
- **Install dependencies:** None. The prototype is one static page with no packages.
- **Run locally:** Double-click `docs/app/index.html`, or run `start docs/app/index.html` (Windows) / `open docs/app/index.html` (Mac). It opens with sample data. Holiday import, PostHog and fonts need internet; everything else works offline.
- **Run with accounts:** works by double-clicking or with `node server.js`; email links (confirm, reset) return to the Site URL set in Supabase. Setup in `supabase/README.md`.
- **Run with AI suggestions:** set up `.env` from `.env.example`, then `node server.js` and open http://localhost:8787/app/. `node server.js --models` lists the models the key can use. Without a key the server still serves the app with AI off.
- **Deploy:** Push to `main`. GitHub Pages republishes `docs/` in about a minute; browsers may cache the old page for up to 10 minutes. Installed home-screen apps pick up the new page on their next launch with a connection; bump `CACHE` in `sw.js` only if a device must drop its old copy.
- **Reset the demo:** Profile tab → **Reload sample data** or **Start empty**. **Simulate next day** tests rollover and streaks.
- **Run deterministic tests:** No automated test suite is committed yet. Before pushing, manually check: add a typed quest (e.g. `exercise 3 times a week`, `coffee chat at 3pm`), use a template chip, complete a quest, claim a reward, import a `.ics` file, tap **Add US holidays** in Schedule, type `send th` and press Tab to accept the suggestion, and check a phone-width window (about 390px). Server tests should use a fake `fetch` (`createServer(env, fakeFetch)`) so they never spend OpenAI credits.
- **Run model evals:** Not set up yet. The only model use is typing suggestions (the `suggest` function live, `server.js` locally); judge them by hand from `node server.js` and PostHog's `suggestion_shown` / `suggestion_accepted` (property `source`: history or ai).

## 3. Non-Negotiable Engineering Rules
1. **Plan before coding:** Before touching multiple files, propose a brief plan and wait for approval.
2. **Small batches:** Make small, focused changes that can be reviewed and explained by a human in a single Pull Request.
3. **Explainability:** Avoid unnecessary abstractions or dependencies. Help the human builder understand the main components, what changed, why it matters, what could break, and how it was checked.
4. **Verify changes:** Run relevant checks. For a reproducible logic bug, use a failing test to demonstrate the fix when practical. Record manual checks and known limitations; follow the selected Build 4 evaluation track.
5. **Zero secrets in code:** Never hardcode API keys, tokens, or credentials. Always read from environment variables (`.env`) and update `.env.example` when new variables are needed.
6. **Stop when looping:** If a fix fails twice in a row, stop, summarize what failed, and ask the human before trying a third approach.

### Rules learned from real mistakes in this project
7. **New Supabase tables need explicit grants.** Newer projects give `anon`, `authenticated` and even `service_role` no table access by default. Sync and reminders both failed with "permission denied" until grants were added. Every new table gets: RLS on, `revoke all ... from anon, authenticated`, only the grants it needs, then a live check and `get_advisors`.
8. **Never copy a secret into tool output or temp files.** An attempt to read `.env` values into a temp file to compare them was (rightly) blocked. Search for key *patterns* instead; ask the human to paste secrets into dashboards themselves.
9. **Read the file before patching it.** Edits failed when text was copied from the unpushed `ai-worker` branch instead of `main`, and shell `sed` patches broke on escaped `\`` and `${`. Use the Edit tool on freshly read text; after two failed patch attempts, switch approach (rule 6).
10. **Browser tests wait for a condition, not a fixed time.** A login test failed randomly after logout because it slept 300 ms; it now waits until the app's state changes.
12. **Escape every value placed in HTML, including attributes and values from our own server.** A paste-review date went into `value="…"` unescaped and could run script. Use `esc()` everywhere, and keep the Content-Security-Policy `<meta>` in `docs/app/index.html` up to date: a new outside service must be added to `script-src` or `connect-src`, or the browser will block it. Re-run the CSP check (no `securitypolicyviolation` events) after changing it.
11. **Check rendered output, not just code.** Duplicate SVG attributes (`fill="none" ... fill="#..."`) silently made drawings see-through, and map labels overlapped until measured in the browser. Screenshot UI changes and run the overlap check after moving map labels.

## 4. Shipping (the steps the agent follows to deploy)
1. **Before changing anything in Supabase:** export a backup of every table to `backups/` (query in `backups/README.txt`; the folder is git-ignored).
2. **Run checks:** the manual checklist in section 2, plus the key search below. It must find nothing except the `.env.example` placeholder and code comments:
   `git grep -nIE 'sb_secret_[A-Za-z0-9]|sk-(or-v1|ant|proj)-[A-Za-z0-9]{8}|sk_live_|sk-[A-Za-z0-9]{32}|PRIVATE KEY-----|VAPID_PRIVATE_KEY=[A-Za-z0-9_-]{20}'`
3. **Show the human what changed and get a "push"**, then commit with the attribution line and `git push origin main` (never force-push).
4. **Verify the live site:** GitHub Pages republishes `docs/` in about a minute. Fetch `https://building-with-ai-f26.github.io/tyt223-dailytask/app/?v=<random>` and confirm a string unique to the change is present, then that PostHog still loads (`posthog.init` in the page).
5. **Database changes** go in a `supabase/*.sql` file first, then `apply_migration` (Supabase MCP), then `get_advisors` (security) and a live permission check with the public key (reads and writes must return `permission denied`).
6. **Edge Function changes:** edit `supabase/functions/<name>/`, deploy every file of that function with `deploy_edge_function` (`verify_jwt: true`), then call it without a login (expect 401) and as the scheduler (expect `{"ok":true}`).
7. **Rollback:** `git revert <commit>` and push for the app; redeploy the previous function files from git for Edge Functions; restore rows from the latest `backups/` file for data.

## 5. Ask me first (never do these without the human's explicit OK in this conversation)
- **Deleting data or changing the database:** `DROP`, `ALTER`, `DELETE`, `TRUNCATE`, migrations, RLS policies, grants, extensions, cron jobs, restoring backups.
- **Keys, secrets and permissions:** creating, rotating or reading keys; Supabase secrets; Auth settings; MCP or Claude Code permissions; git config.
- **Anything that costs money:** paid plans, paid API calls (including real OpenAI requests), new hosted services.
- **Hard-to-undo git actions:** force-push, rewriting history, deleting branches, deleting files outside the scratchpad.
